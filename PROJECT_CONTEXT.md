## What this app is

**BLUBLUB** is a private, mobile-first web app for one couple ("a cozy private space for two").
Two people pair with an invite code and share: a home dashboard, calendar, chat, photo
memories, diary, to-dos, bucket list, budget, daily questions, wellbeing tools (cool-down,
cycle tracking, commitments, map), a decorated shared room ("Our Room") and a game corner.

- Live app: https://blublub-together-always.lovable.app
- Built and hosted with **Lovable**; this GitHub repo syncs both ways with the Lovable editor.
- Also wrapped as a phone app (Capacitor) from a static build.

## How the code is organised

```
src/
  routes/                 one file per page; `_authenticated/` holds every signed-in page
    __root.tsx            app shell, fonts, saved theme applied on load
    _authenticated/route.tsx   what stays on screen between pages (tab bar, chat head, side menu)
  components/             shared UI (AppLayout, BottomNav, ui-kit, Doodles = mascots)
    games/                the two-player "loser task" games + their shared pixel pieces
    room/                 Our Room stage
    ui/                   shadcn/ui primitives (generated; avoid editing)
  arcade/                 SOLO ARCADE MODULE (canvas games). Self-contained — see below
  lib/                    data hooks and helpers (one file per feature)
  integrations/supabase/  generated Supabase client + types (do not edit by hand)
  styles.css              design tokens (CSS variables) + shared utility classes + game motion
  skins.css               the 8 app styles ("skins"): classic, pixel, jelly, glass, scrapbook,
                          cyberpunk, steampunk, nature
supabase/migrations/      database history (applied by Lovable/Supabase, not by us)
tests/                    bun tests for pure game logic
```

### Page pattern

Every page is `createFileRoute(...)` + a component wrapped in `<AppLayout title subtitle>`.
`AppLayout` draws the header and applies the couple's theme; the tab bar lives in
`_authenticated/route.tsx`. `src/routeTree.gen.ts` is generated by the router plugin when the
dev server or a build runs — never edit it by hand, but do commit it.

### Theme system (important)

Two independent layers:

1. **Colours** — the couple picks colours; `applyColors()` in `src/lib/theme.ts` writes them to
   CSS variables (`--primary`, `--secondary`, `--accent`, …) on `<html>`. Saved in
   `couples.theme` and mirrored to `localStorage["blublub-theme-v2"]`.
2. **Skin** (app style) — `<html data-skin="…">` selects a block in `src/skins.css` which
   restyles the *shared* classes (`.card-soft`, `.surface-quiet`, `.tile-*`, buttons, inputs,
   header, tab bar). Skins change shape, font, material and motion — not the couple's colours
   (Cyberpunk is the one exception: it brings its own dark palette with `!important`).

So: always build screens from the shared classes and CSS variables, never hard-coded colours,
and every skin keeps working.

### Mascots

`<Doodle critter="cat|seal|penguin" pose="…">` draws a soft PNG in most skins and a 24×24
pixel sprite in the Pixel skin (both are rendered; CSS shows one). Sprite data lives in
`src/components/pixel-critters.ts`. Inside a `.pixel-zone` the pixel version always shows.

## Games — two kinds

| | Two-player "loser task" games | Solo arcade games |
| --- | --- | --- |
| Where | `src/components/games/` | `src/arcade/` |
| Examples | Tic-Tac-Toe, RPS, Memory, Connect Four, War | Hop Up (platformer), Wing It (flap) |
| Drawn with | React + CSS (pixel look via `.pixel-zone`) | `<canvas>`, own tiny engine |
| Saved in | Supabase table `games` (shared, realtime) | `localStorage` on the device only |
| Route | `/games/$kind` | `/games/play/$game` |

**House rule for all games: pixel-art graphics in every skin**, to match Our Room (whose
furniture and backgrounds are a pixel-art pack).

### The arcade module (`src/arcade/`) — *being built, see TASK_TRACKER.md*

Deliberately separate from the app's business logic:

- `engine/` — fixed-step game loop, pixel sprite drawing, input, particles, sound helper.
- `games/<name>/logic.ts` — **pure** game rules (no DOM, no React). Unit-tested.
- `games/<name>/render.ts` — draws a game state onto a canvas context.
- `ArcadeCabinet.tsx` — the one React component that hosts any arcade game: title screen,
  playing, paused, game over, score and best score.
- `scores.ts` — best scores in `localStorage` (never Supabase).
- `registry.ts` — list of arcade games. The app only imports the registry and the cabinet.

The app talks to the arcade through exactly two things: the registry (for menus) and
`<ArcadeCabinet game={…} />`. Nothing in `src/arcade/` imports app data hooks or Supabase.

## Decisions that must be respected

1. **Use Supabase as little as possible** (owner's instruction, 2026-11-10). New features must
   work without new tables or columns. Prefer on-device storage. Do not run tools against the
   Supabase project. Existing features keep the Supabase wiring they already have.
2. **Never rewrite published git history** (no force-push, rebase, amend or squash of pushed
   commits) — Lovable mirrors the history (see `AGENTS.md`).
3. **Do not edit generated files**: `src/integrations/supabase/*`, `src/routeTree.gen.ts`,
   `src/components/ui/*`.
4. **No new dependencies without the owner's approval.** `bun.lock` points some packages at
   Lovable's private mirror; changing it carelessly can break Lovable's build.
5. **Mobile first.** Touch-friendly, no hover-only controls, safe-area padding. Anything that
   takes drags/taps over a large area needs `data-no-page-swipe` (pages change on swipe).
6. **Respect "reduce motion".** Every animation gets a `prefers-reduced-motion` fallback.
7. Sounds go through `playChirp()` (`src/hooks/use-sound.ts`) so the user's sound switch works.

## Known quirks

- The README still mentions an older Supabase project id; the code uses the project in
  `src/integrations/supabase/client.ts`.
- `eslint .` reports ~2,700 problems, almost all pre-existing formatting (prettier) differences
  in older files. `tsc` is clean. New/changed files should be lint-clean; do not mass-reformat
  old files (it would bury real changes in the history).
- Our Room furniture/background images are served from Lovable's asset store
  (`/__l5e/assets-v1/...`), so they only load on Lovable hosting, not on a local dev server.
